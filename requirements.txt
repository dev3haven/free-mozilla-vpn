# ============================================================================
# Free Mozilla VPN (mozvpn_beta.py) — RUNTIME dependencies.
#
# This is THE single source of truth for the script's runtime deps; the
# CI workflow (release.yml) only runs `pip install -r requirements.txt`
# and FAILS if it cannot be satisfied — nothing runtime-related is
# pinned or hardcoded in the workflow.
#
# Direct runtime deps of mozvpn_beta.py:
#   pyotp      — TOTP code generation (REQUIRED for 2FA)
#   zxing-cpp  — QR decoding (REQUIRED to read 2FA QR images)
#   Pillow     — image opening for the QR loader (REQUIRED)
#   aioquic    — real MASQUE / HTTP-3 CONNECT-UDP probing (REQUIRED;
#                without it every upstream falls back to HTTP CONNECT)
#
# Transitive dependency of aioquic that needs an explicit constraint:
#   cryptography — aioquic requires `cryptography>=42.0.0`. Two problem
#                 platforms in the CURRENT release line (50.x, Aug 2026):
#                   * win_arm64: no wheel at all — pyca dropped them
#                     after 46.0.3 (pyca/cryptography#14249,
#                     crossbario/autobahn-python#1945);
#                   * win32 (32-bit Windows): support REMOVED — the
#                     changelog deprecated 32-bit Windows in the 46.x
#                     line ("will be removed in two releases") and 50.0.1
#                     states "BACKWARDS INCOMPATIBLE: Support for 32-bit
#                     Windows has been removed".
#                 On both platforms pip falls back to the sdist and tries
#                 a Rust/maturin build, which dies with "Could not find
#                 directory of OpenSSL installation". 46.0.3 is the last
#                 release line that ships wheels for win32, win_amd64 AND
#                 win_arm64; the abi3 wheels are forward-compatible
#                 across Python 3.x (so 3.14 is fine) and still satisfy
#                 aioquic's `cryptography>=42.0.0`.
#                 The pin is applied to ALL Windows via the PEP 508
#                 marker `sys_platform == "win32"` — uniform and immune
#                 to the platform_machine() ambiguity of 32-bit Python
#                 under WOW64. Linux and macOS keep resolving to the
#                 latest release, which has prebuilt wheels there (on
#                 i686 Linux the workflow apt-installs pkg-config +
#                 libssl-dev so the sdist build succeeds).
#                 TERMUX (Android): the marker does NOT apply there
#                 (sys_platform == "linux"), so pip would resolve the
#                 latest release and try a Rust/maturin sdist build —
#                 instead the workflow pre-installs Termux's own
#                 prebuilt package `python-cryptography` (45.0.3 in
#                 termux-packages) BEFORE `pip install -r
#                 requirements.txt`; pip then sees the requirement
#                 `cryptography>=42.0.0` already satisfied and never
#                 rebuilds it. Same trick for Pillow (`python-pillow`
#                 Termux package).
# ============================================================================

pyotp
zxing-cpp
Pillow
aioquic
cryptography==46.0.3; sys_platform == "win32"
