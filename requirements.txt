# ============================================================================
# Free Mozilla VPN (mozvpn.py) — RUNTIME dependencies.
#
# This is THE single source of truth for the script's runtime deps; the
# CI workflow (release.yml) only runs `pip install -r requirements.txt`
# in EVERY build environment — the Windows runner cells, the Debian 13
# "trixie" glibc containers, the Alpine 3.24 musl containers and the
# Termux environment — and FAILS if it cannot be satisfied; nothing
# runtime-related is pinned or hardcoded in the workflow. The two
# files are verified IN SYNC (2026-10-31): the workflow quotes the
# pin line below verbatim, installs the system headers this file's
# comments promise (apt in the trixie glibc containers, apk in the
# Alpine musl containers) and pre-installs the Termux packages
# described below BEFORE running pip against this file.
#
# Direct runtime deps of mozvpn.py:
#   pyotp      — TOTP code generation (REQUIRED for 2FA)
#   zxing-cpp  — QR decoding (REQUIRED to read 2FA QR images)
#   Pillow     — image opening for the QR loader (REQUIRED)
#   aioquic    — real MASQUE / HTTP-3 CONNECT-UDP probing (REQUIRED;
#                without it every upstream falls back to HTTP CONNECT)
#
# Transitive dependency of aioquic that needs an explicit constraint:
#   cryptography — aioquic requires `cryptography>=43.0.0` (aioquic
#                 1.7.0, verified on PyPI 2026-10-31). Two problem
#                 platforms in the current release line (50.x; latest
#                 50.0.2, released 2026-09-30):
#                   * win_arm64: no wheel at all — pyca dropped them
#                     after 46.0.3 (pyca/cryptography#14249,
#                     crossbario/autobahn-python#1945);
#                   * win32 (32-bit Windows): support REMOVED — the
#                     changelog deprecated 32-bit Windows in the 46.x
#                     line ("will be removed in two releases") and 49.0.0
#                     (2026-06-12) states "BACKWARDS INCOMPATIBLE: Support
#                     for 32-bit Windows has been removed".
#                 On both platforms pip falls back to the sdist and tries
#                 a Rust/maturin build, which dies with "Could not find
#                 directory of OpenSSL installation". 46.0.3 is the last
#                 RELEASE shipping wheels for win32, win_amd64 AND
#                 win_arm64 (its successor 46.0.4 already dropped
#                 win_arm64; 49.0.0 dropped win32); the abi3 wheels are
#                 forward-compatible across Python 3.x (so 3.15 is fine)
#                 and still satisfy aioquic's `cryptography>=43.0.0`.
#                 The pin is applied to ALL Windows via the PEP 508
#                 marker `sys_platform == "win32"` — uniform and immune
#                 to the platform_machine() ambiguity of 32-bit Python
#                 under WOW64. LINUX (glibc AND musl) keeps resolving
#                 to the latest release: prebuilt manylinux AND
#                 musllinux_1_2 wheels exist for x86_64/aarch64; on the
#                 32-bit x86 cells the sdist builds succeed because
#                 the workflow installs the system headers first —
#                 pkg-config + libssl-dev via apt (Debian 13 trixie
#                 glibc container) and pkgconf + openssl-dev via apk
#                 (Alpine 3.24 musl container), plus zlib1g-dev +
#                 libjpeg-dev (glibc) / zlib-dev + jpeg-dev (musl) for
#                 the Pillow sdist; the Rust toolchain for the
#                 cryptography sdist is fetched by its build backend
#                 itself (seen live; FIX 10 in release.yml). macOS is
#                 not targeted by this workflow; note that the latest
#                 releases ship macOS arm64 wheels only. FORWARD-LOOKING:
#                 the unreleased 51.0.0 changelog requires "CFFI 2.1.1
#                 or newer on Python 3.15 to avoid an ABI issue" —
#                 recheck this pin before ever unpinning cryptography
#                 on Windows Python 3.15.
#                 TERMUX (Android): the marker does NOT apply there
#                 (sys_platform == "linux"), so pip would resolve the
#                 latest release and try a Rust/maturin sdist build —
#                 instead the workflow pre-installs Termux's own
#                 prebuilt package `python-cryptography` (50.0.2 in
#                 termux-packages, verified 2026-10-25) BEFORE `pip
#                 install -r requirements.txt`; pip then sees the
#                 requirement `cryptography>=43.0.0` already satisfied
#                 and never rebuilds it. Same trick for Pillow
#                 (`python-pillow` Termux package).
# ============================================================================

pyotp

Pillow
aioquic
cryptography==46.0.3; sys_platform == "win32"
